# SCRUM-17: Revision y Aprobacion de Pull Requests\n\n## Objetivo\nEstablecer proceso formal de revision y aprobacion de PRs garantizando estandares de calidad.\n\n## Criterios de Aprobacion\n- Cobertura de pruebas >= 80 pct\n- Sin errores de linting (flake8, pylint)\n- Sin vulnerabilidades de seguridad\n- Revision de al menos 1 miembro del equipo\n- CI/CD pipeline en verde\n\n## Checklist de Revision\n- [ ] Tests pasan correctamente\n- [ ] Cobertura no disminuye\n- [ ] Codigo cumple guia de estilo\n- [ ] Documentacion actualizada\n- [ ] Sin conflictos con main\n\n## Flujo de Trabajo\n1. Desarrollador crea rama desde Jira\n2. Realiza commits con mensajes convencionales\n3. Crea Pull Request con descripcion detallada\n4. QA revisa y aprueba o solicita cambios\n5. Merge a main tras aprobacion\n
